How the flake is wired

The repository is built around host data. A host attrset describes users, desktop choices, graphics, services, network behavior, and macOS Dock settings. Builders turn that host data into OS and Home Manager configurations.

Top-level flow

1configs/flake.nix imports every configs/hosts/*.nix file into an attrset keyed by filename.
2flake.nix maps each host name through mkConfig.
3Names ending in x86 become x86_64-linux; names ending in aarch64 become aarch64-linux; everything else becomes aarch64-darwin.
4utils/default.nix creates mkHomeConfig, mkNixConfig, and mkDarwinConfig.

Important inputs

Input Purpose
nixpkgs, nixpkgs-stable Main package set plus a stable channel.
home-manager, darwin User-level and macOS system builders.
stylix Shared theme, fonts, wallpaper, icons, and cursor styling.
plasma-manager Declarative KDE Plasma settings.
nixcord, spicetify-nix, zen-browser Discord/Vesktop, Spotify, and browser integrations.
mango NixOS module for MangoWC.
treefmt-nix Repository formatter wrapper.

Special arguments

utils/default.nix passes common arguments to every module: flakeConfig, linux, darwin, overlays, selected inputs, and allowUnfreePredicate.

flakeConfig

The current host attrset from configs/hosts.

linux / darwin

Platform booleans used to gate modules cleanly.

extraOverlays

Adds discord-rpc-lsp and the ip overlay.

allowUnfreePredicate

Allows selected unfree packages such as Spotify, Steam, Discord, Shottr, and NVIDIA packages.

Module imports

Both modules/config/default.nix and modules/home/default.nix use custils.lib.getModulesFromDirRec, so new .nix modules are picked up automatically. NixOS additionally imports the host hardware module.
